# SUNGSUYA 프로젝트 지침 작성요령 v1.1

**문서 목적**: 프로젝트 지침 업데이트 시 정확하고 일관된 작성을 위한 상세 가이드  
**적용 대상**: AI 개발 도우미들  
**최종 업데이트**: 2025년 8월 5일

## 🎯 프로젝트 지침의 역할과 특성

### 지침 vs 지식의 명확한 구분
```
📋 프로젝트 지침 = "지금 당장 작업하기 위한 실무 매뉴얼"
├── 현재 상태 중심
├── 즉시 사용 가능한 정보
├── 과정보다는 결과 위주
└── 협업 효율성 최우선

📚 프로젝트 지식 = "왜 이렇게 되었는가를 알기 위한 기록 보관소"
├── 변화 과정 기록
├── 문제 해결 히스토리
├── 의사결정 배경
└── 학습 자료 보존
```

### 지침 업데이트가 필요한 시점
- ✅ **환경 정보 변경**: 로그인 정보, URL, DB 설정 등
- ✅ **파일 구조 변화**: 주요 파일 추가/삭제/이동/개수 변화
- ✅ **시스템 현황 변화**: Places 개수, 팝업스토어 개수, 기능 상태 등
- ✅ **작업 우선순위 변화**: Critical Priority 항목 완료/추가/변경
- ✅ **테스트 방법 변화**: 새로운 기능 추가로 인한 테스트 절차 변경
- ✅ **도구/버전 업데이트**: 중요 시스템 버전 변경

## 📋 파일 명명 규칙 (2025년 8월 업데이트)

### 가이드 파일명 체계
```
sungsuya-guide-v[X.Y].md

예시:
- sungsuya-guide-v1.0.md   (원본 가이드 - 프로젝트 초기)
- sungsuya-guide-v1.5.md   (현재 최신 가이드 - v1.0~v1.4 반영)
- sungsuya-guide-v1.6.md   (다음 가이드 - v1.5 반영 예정)
- sungsuya-guide-v2.0.md   (메이저 업데이트)
```

### 버전 번호 체계
- **Major.Minor** (예: v1.0, v1.5, v2.0)
- **Minor 증가**: 개발 보고서 1~4개 반영 시
- **Major 증가**: 큰 기능 추가, 아키텍처 변경, 프로젝트 구조 변화

### 연관 문서 체계
```
프로젝트 가이드:
- sungsuya-guide-v1.0.md   (원본)
- sungsuya-guide-v1.5.md   (현재 최신)

개발 보고서:  
- sungsuya-report-v1.0.md ~ v1.4.md

작업 매뉴얼:
- sungsuya-manual-reports.md
- sungsuya-manual-guides.md  (이 문서)
```

## 🎯 프로젝트 개요
```

**작성 원칙:**
- 항상 "개발자를 위한" 관점에서 작성
- 버전 정보는 실제 확인된 것만 명시
- 현재 상태를 명확히 표현

### 2. 환경 정보 섹션
```markdown
## 🌐 개발 환경

### 로컬 개발환경
- **URL**: https://sungsuya.local (정확한 접속 URL)
- **상태**: 완전 정상 작동 (v1.4에서 모든 문제 해결)
```

**작성 원칙:**
- URL은 실제 테스트해서 접속되는 것만 명시
- 상태는 최신 테스트 결과 반영
- 버전 정보는 해결된 문제와 연결하여 명시

### 3. 로그인 정보 섹션 (중요!)
```markdown
## 🔑 로그인 정보

### 관리자 계정
- **사용자명**: `dcclab2022`
- **비밀번호**: `temp123!` (임시, 모든 개발 작업 완료 후 변경 예정)
```

**⚠️ 작성 시 주의사항:**
- 비밀번호는 반드시 최신 상태로 유지
- 임시/영구 여부 명확히 표시
- 보안 관련 주의사항 반드시 포함

### 4. 협업 연락처 및 자료 섹션 (필수!)
```markdown
## 📞 협업 연락처 및 자료

### 개발 문서 위치
```
C:\Project\sungsuya\docs\
├── sungsuya-guide-v1.0.md             # 원본 가이드
├── sungsuya-guide-v1.5.md             # 현재 최신 가이드 (이 문서)
├── sungsuya-report-v1.0.md ~ v1.4.md  # 개발 보고서들
├── sungsuya-manual-reports.md         # 보고서 작성 지침
└── sungsuya-manual-guides.md          # 가이드 작성 요령
```

### 백업 위치
```
주요 백업 경로:
├── FastComet 실서버 (최종 안전 백업)
├── C:\Project\sungsuya\ (프로젝트 원본 백업)
└── C:\Project\sungsuya\backup-before-cleanup\ (버전별 백업)
```
```

### 5. 현재 시스템 지표 섹션 (자주 업데이트)
```markdown
### 현재 시스템 지표
- **Places 현황**: 35개 (좌표 생성 100% 완료)
- **팝업스토어**: 12개+ 등록됨 (메인페이지에는 최근 4개만 표시)
```

**⚠️ 정확성 필수:**
- 실제 카운트 확인 후 작성
- 메인페이지 vs 전체 페이지 구분
- 상태별 분류 (운영중, 종료됨 등)

### 6. 우선순위 작업 섹션
```markdown
### 다음 우선순위 작업 (Critical Priority)
```
🗓️ 1. 팝업스토어 날짜 표시 오류 해결
   → 모든 팝업스토어가 "1.1 - 1.1"로 동일 표시되는 문제
   → 실제 운영 기간이 제대로 표시되지 않아 사용자 혼동 야기
```

**작성 원칙:**
- 구체적인 증상 명시
- 사용자에게 미치는 영향 설명
- 재현 방법 또는 확인 방법 제시

#### Places 개수
```markdown
✅ 올바른 확인 방법:
1. wp-admin > 장소 > 모든 장소에서 실제 개수 확인
2. 또는 메인페이지에서 "35개의 트렌디한 공간이..." 문구 확인

❌ 잘못된 방법:
- 이전 보고서의 수치 그대로 복사
- 대략적인 추정치 사용

#### 팝업스토어 개수
```markdown
✅ 올바른 확인 방법:

2. 현재 페이지의 팝업스토어 개수 세기
3. 페이지네이션 확인 ("2", "다음" 버튼 등)
4. 메인페이지 필터와 전용 페이지 수치 구분하여 기록

예시: "12개+ 등록됨 (메인페이지에는 최근 4개만 표시)"
